## 2. Не делаем (осознанно, с причинами)

| Что | Почему | Триггер для пересмотра |
|---|---|---|
| Копии текстов СП/ГОСТ в git/distro | L0-N no_full_copies (авторские права, реестр Минцифры, верифицируемость) | никогда (только в приватном контуре evidence) |
| Правила валидации в графовой БД | источник истины — git (rebuildable проекция, §5.2 Concept) | никогда |
| Каждая ячейка таблицы = узел графа | взрыв графа, без пользы (γ) | — |
| Графовая БД (Neo4j) на старте | холодный старт, Phase 2 при масштабе (ADR-013) | размер графа > ~10⁵ узлов или нужны графовые запросы в продукте |
| Свой BRep/IFC-парсер | IfcOpenShell + IfcTester закрывают задачу (ADR-013) | никогда (если экосистема не загнётся) |
| Свой DSL правил | усложняет G-2; YAML/JSON Schema достаточно | никогда |
| Сложные расчёты (свой конечный элемент) | BASE/ЛИРА/SCAD через адаптеры; BRAIM = проверка (D-08) | никогда |
| Облачные LLM по умолчанию для агентов | G-6 (клиентские данные) | только публичные нормы (F-06) |
| Канти-фичи | малый бюджет времени автора (12–16 ч/нед) | M4+ |
| Renga-коннектор сейчас | госвектор, не в приоритете (решение автора 2026-10-16) | M3+, при наличии заказчика Renga |
| Реестр Минцифры (подача) | registry-ready позиция; решение — отдельная веха (D-11) | до M3+ |

## 3. Граничные решения (требуют ответа автора)

- **Сроки:** 12–16 ч/нед (F-10) — вехи рассчитаны под этот режим
- **AI-выбор Ollama-модели:** qwen3b (быстро) vs qwen7b (качественно) — проба показала, что обе на юридическом русском выдают тонкие критерии; few-shot промпт с примерами автора — следующий шаг
- **Сценарии использования:** 5 вертикалей (АГР/Стройэкспертиза/ОПР/КМ-КМД/Библиотеки); 1 (АГР) Phase 1, 2 (Стройэкспертиза) Phase 2
- **Нормативная база:** bSDD-совместимый BRAIM Pset (DICT-02) + двуязычный словарь (ru+en)
