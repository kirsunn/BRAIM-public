# SPECIFICATION_FORMULA_v0.2

**Статус:** draft_for_review

**Контекст:** BRAIM-public, docs/agents/
**Связанные:** ADR-0004 (не принят), ADR-0005, ADR-0006, ADR-0007, ADR-0008, ADR-0009, LINKING_MODEL_v0.1, NORMA_unified_working_package_v0.3, DESIGN_ITERATION_v0.1, ROLES.md

## Назначение

Этот документ фиксирует доменную формулу формирования технического задания.

Он создан, чтобы сохранить содержательную формулу из драфта `BAIM_PROJECT_CONTEXT.md` при переводе AVGALAXY-метафоры во внутренний архитектурный паттерн.

## Evidence

Основание для статуса `draft_for_review`:

```text
FORMULA_TRACE_2026-10-20.md
```

Вывод trace-отчёта:

```text
Формула «ТЗ = нормы + ситуация + оператор»
не найдена в утверждённых источниках.

Она вводится как новое доменное предложение.
```

## Формула

```text
Применимые нормативные требования
+ текущее состояние проекта
+ цели, ограничения и решения уполномоченного участника
→ функция оркестрации проекта
→ техническое задание
→ требования и проверяемые критерии
→ IFC / IDS
→ валидация
→ история изменений
→ аналитика
→ следующая итерация.
```

## Доменная формулировка

Техническое задание формируется на основе:

- применимых нормативных требований;
- текущего состояния проекта;
- целей, ограничений и решений уполномоченного участника.

Функция оркестрации проекта преобразует эти входы в:

- структурированное техническое задание;
- требования;
- проверяемые критерии;
- основания для валидации IFC-модели и IDS-правил;
- фиксацию истории изменений;
- аналитику;
- вход следующей итерации.

## Определения

### Функция оркестрации проекта

```text
Функция оркестрации проекта —
функция, которая преобразует входы
в техническое задание,
требования и проверяемые критерии.
```

В v0.2 «функция оркестрации проекта»
не вводится как отдельная таксономическая сущность.

Вопрос о том, нужна ли для неё
отдельная сущность, модуль или роль,
остаётся открытым.

### Уполномоченный участник

```text
Уполномоченный участник — роль,
которая имеет право подтвердить цель,
ограничения и ответственные решения.
```

В v0.2 термин не отображается
на конкретную роль из ROLES.md.

Соответствие ролям ROLES.md — открытый вопрос.

## Статусы сверки

Используются четыре исхода:

```text
coincides — смысл совпадает с утверждённым источником.
diverges — смысл расходится; требуется решение.
new — в утверждённых источниках содержания нет.
pending_source_review — Excerpts не предоставлены
или сверка не завершена.
```

## Acceptance criteria

Документ может перейти в `accepted`, только если:

1. Формула сформулирована только в доменных терминах.
2. Ни один элемент формулы не зависит от AVGALAXY-метафоры.
3. Для каждого входа и выхода указан источник или статус `new`.
4. «Функция оркестрации проекта» определена как функция, а не таксономическая сущность.
5. «Уполномоченный участник» имеет явное правило сопоставления с ROLES.md.
6. Все строки сверки имеют статус `coincides`, `diverges`, `new` или `pending_source_review`.
7. ADR-0004 может быть открыт только после перехода документа в `accepted`.

## Что не входит

Этот документ не определяет:

- автоматическую генерацию проектных решений;
- изменение LINKING_MODEL;
- изменение DESIGN_ITERATION;
- изменение ROLES;
- правку архивного BAIM_PROJECT_CONTEXT.md;
- принятие ADR-0004.
