# Источник: рекомендация по таблицам и графу

> **Провенанс:** 2026-10-17, импортирован из Perplexity file gateway (BAIM_Roadmap_v0_1). Источник одобрен автором (γ — заложить основу графа сейчас, минимальным, проверяемым). Сохранён как **референс** для разработки, не как регламент.
>
> Использование: гайд по hybrid-пайплайну и по модели графа. В наш документ `docs/graph/SCHEMA_v0_1.md` перенесены конкретные решения, адаптированные под BRAIM.

## Рекомендуемый пайплайн (референс)

```text
PDF → определение страницы/таблицы → извлечение ячеек + координат
    → восстановление заголовков и объединённых ячеек
    → нормализация в JSON/CSV
    → LLM-классификация и маппинг в онтологию
    → валидация правил
    → графовая БД
```

## Hybrid для нашего контура (решение 2026-10-17)

- **Извлечение:** `pdfplumber` (текстовый слой) + `Tesseract` (сканы) — оба уже доступны на ПК автора
- **Структурирование:** pandas + восстановление заголовков
- **Семантика:** Лингвист получает не сырой PDF, а JSON-таблицу с заголовком/сносками/единицами/контекстом
- **Граф:** в Python (NetworkX) — мгновенный запуск, без внешних сервисов; Neo4j — позже при масштабе (ADR-013)

## Модель графа (референс, доработанная в нашей версии)

| Объект | Узел | Пример |
|---|---|---|
| Документ | `Document` | `SP 64.13330` |
| Таблица | `Table` | «Таблица 6.1 — Нормативные нагрузки» |
| Параметр | `Parameter` | `snow_load`, `fire_rating`, `min_width` |
| Условие | `Condition` | «здание класса Ф1.2», «высота ≤ 28 м» |
| Правило | `Rule` | `IF condition THEN requirement` |
| Свойство | `Property` (BAP) | наше измерение (BRAIM Pset), связь с bSDD-определением |
| Источник | `SOURCED_FROM` | `Rule → Table → Document` |
| Связь с BIM | `APPLIES_TO` | `Rule → WallType/Room/System` |

Ключевая поправка для BRAIM: **критерий (norm-criterion.json) и Rule в графе — сущности с разной гранулярностью**: Criterion = нормализованное требование (что проверяем), Rule = применение условий (если высота > X → правило Y). Criterion ↔ Rule — связь `IMPLEMENTED_BY`.

## Что важно не потерять (прям в схему)

- **Координаты и страница:** `page`, `bbox`, номер таблицы/строки — иначе нельзя верифицировать
- **Сноски и примечания** меняют смысл всей таблицы
- **Объединённые ячейки** — заголовок на несколько строк
- **Единицы** отдельно и в нормализованном виде
- **Операторы** «не менее», «до», «при» — это Condition, не значение
- **Версия документа** — без неё правило небезопасно

## Мой вердикт из референса (принят)

> PDF → таблицы с provenance → JSON-промежуточный → нормализованные правила → граф (NetworkX в Python → Cypher-seed для Neo4j). Слабое место — **семантическая интерпретация**: MVP на 3–5 таблицах одного СП + ручная фиксация схемы графа, потом масштабирование.
