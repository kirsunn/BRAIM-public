# BRAIM Threat Model v0.1 (draft)

**Дата:** 2026-10-15 · **Статус:** draft — требует подтверждения автора (R-16)
**Scope:** Phase 1, пилот «заказчик = мы», пилотный объект — собственная АГР-модель

---

## 1. Данные и классификация

| Данные | Классификация | Где живут |
|---|---|---|
| Код, спеки, схемы, модели-документы | **Публичное** | GitHub (BRAIM-public, BRAIM) |
| Пилотные АГР-модели (IFC-экспорты) | **Внутреннее** (низкая чувствительность: свои данные, без ПДн и гостайны) | Локально (`D:\BRAIM` + фолбэк-хранилище), в git — только обезличенные корпусные модели |
| Отчёты валидации, LC/classification записи, evidence | **Внутреннее** | Реестр Phase 1, git |
| Словари/таблицы (bSDD-совместимые) | **Публичное** | git + pinned snapshots |
| Персональные данные | **Отсутствуют** в контуре Phase 1 | — |

## 2. Акторы и риски

| Актор | Риск | Мера |
|---|---|---|
| Автор (единственный разработчик) | Единственная точка отказа: потеря машины/данных | Git для всего текстового; модели — фолбэк-хранилище + второй носитель. **Резервное копирование пока не решено — открытое решение** |
| ИИ-ассистенты (полный доступ к рабочей папке) | Повреждение данных / случайная публикация | Всё через git (откат); пуш только по явному решению; модели не в git без обезличивания |
| GitHub (публичные репо) | Утечка чувствительного | Правило: АГР-модели и данные пилота — только локально/фолбэк, не в публичные репо; проверка перед пушем |
| Локальное железо (соцконтракт-сервер, СНГ/СНТ) | Физическая безопасность, питание | ИБП в смете соцконтракта; шифрование диска — решение открыто |
| Третьи лица | Низкий риск: контур solo | OIDC (AD-04) отложен до мульти-пользовательского режима |

## 3. Правила Phase 1 (вытекающие)

1. Публичные репо — только код/спеки/словари; модели пилота — вне публичного.
2. Каждый артефакт — с provenance и digest (уже в схемах).
3. Словарные snapshots — offline-копии, лицензии словарей проверять при подключении (DICT-04).
4. Экспорт АГР-модели в корпус — с обезличиванием имён/адресов, если модель станет публичной.

## 3.1. Git visibility policy (решение 2026-10-16)

- git (GitHub) — **только наш оригинальный контент**: код, спеки, модели-документы, словари.
- Сторонние материалы (эталоны МГГТ, PDF-документы, дампы КСИ) — **вне git** (`_library/`, бэкап на Яндекс.Диск).
- Пилотные модели заказчиков — **никогда не в git**.
- Резервирование: rclone → Яндекс.Диск (основное), Google Drive — вторичная копия критичного (F-09).

## 4. Открытые решения (нужно от автора)

1. **Резервное копирование:** куда и как часто (второй носитель / облачное / git-LFS для моделей).
2. **Фолбэк-хранилище:** локальная папка vs S3-compatible (MinIO local vs облако) — влияет на threat surface.
3. Шифрование диска сервера: да/нет.
4. Подтвердить/скорректировать классификацию из §1.
