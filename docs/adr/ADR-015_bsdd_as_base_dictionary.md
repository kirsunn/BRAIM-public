# ADR-015: bSDD как базовый словарь BRAIM

- **Статус:** Accepted (draft → first review при Phase 1 close)
- **Дата:** 2026-10-15
- **Относится к:** Attribute Registry v0.1.1, Classification Model v0.1.1 (CL-05/CL-06), policy packs (D-03), IDS-валидация (Phase 2)
- **Источники:** [buildingSMART Technical — Underlying ISO standards (bSDD)](https://technical.buildingsmart.org/services/bsdd/underlying-iso-standards), [github.com/buildingsmart/bSDD](https://github.com/buildingsmart/bSDD), [IDS + bSDD (MDPI Buildings, 2025)](https://www.mdpi.com/2075-5309/15/3/378), [openBIM Knowledgebase §10.2](https://openbim-knowledgebase.org/en/docs/chapter-10-digital-requirements-for-manufacturers-of-construction-products-and-building-materials/chapter-10-2-buildingsmart-data-dictionary-bsdd)

---

## 1. Контекст

**bSDD (buildingSMART Data Dictionary)** — онлайн-словарь buildingSMART, реализующий **ISO 12006-3** и **ISO 23386** (словари данных): классификации, определения свойств (тип, единица, допустимые значения), материалы, переводы. Официально интегрирован с IDS — IDS-политики могут ссылаться на определения свойств из bSDD. Сервис развивается (API v2→v3), поддерживает custom dictionaries.

Attribute Registry BRAIM (v0.1) определял свойства локально, словарный слой отсутствовал: типы, единицы и значения описывались ad-hoc — риск рассинхронизации с IDS-политиками и внешними системами.

**Решение автора (2026-10-15):** взять bSDD за основу словарной системы BRAIM. Форма хостинга проектных определений — локальный реестр с bSDD-совместимой моделью; подключение — с Phase 1.

## 2. Решения

| ID | Решение | Смысл |
|---|---|---|
| DICT-01 | **bSDD — базовый словарь** | Термины, определения свойств, единицы, допустимые значения — по ISO 12006-3/23386 через bSDD; собственные словари не создаются без необходимости |
| DICT-02 | **Проектные определения — локальный реестр с bSDD-совместимой моделью** | Свойства/таблицы пилота ведутся у себя (полный контроль, оффлайн-валидация, свои темпы); модель данных совместима с bSDD (definitions, translations, relations); экспорт в bSDD custom dictionary — опционально, при готовности |
| DICT-03 | **Подключение с Phase 1** | IDS-политики и policy packs с первого прогона ссылаются на словарные определения: bSDD URI/GUID, где определение существует; локальные bSDD-совместимые id — для проектных |
| DICT-04 | **Pinning словарей как артефактов** | Используемые словари/версии фиксируются в policy pack (edition + digest, по аналогии с CL-05); **runtime-валидация не обращается к внешнему сервису** — детач-исполнение и воспроизводимость |
| DICT-05 | **Mapping классификаций через bSDD-механику** | Связи `IsEqualTo`/`HasSimilarity` между классификациями в bSDD — предпочтительный способ mapping profile (CL-06); иначе — собственный версионируемый mapping |
| DICT-06 | **Языки пилота: ru + en** | Определения ведутся двуязычно (bSDD поддерживает переводы); КСИ-связка — через mapping, не через перевод терминов |

## 3. Соответствие механизмам BRAIM

| Механизм | Изменение |
|---|---|
| Attribute Registry → v0.1.1 | Поле `bsdd_property_ref` (URI/GUID bSDD PropertyDefinition); правило: при наличии словарного определения локальное переопределение типа/единицы — расхождение |
| Classification Model → v0.1.1 | `table_ref.system` += `bSDD`; таблицы могут быть sourced/hosted через bSDD; mapping — через связи bSDD (DICT-05) |
| Policy packs (D-03) | Манифест перечисляет используемые словари + версии (DICT-04); IDS-политики ссылаются на те же определения |
| Layer Model L1-C/L0-N | Канонические определения свойств — словарные; нормы остаются в L0-N (bSDD — не нормативный источник, R-05 не отменяется) |
| ИИ-направление | `no_ai_as_norm` распространяется на словарь: AI_PROPOSED определения — только через реестр и подтверждение (Attribute Registry, правило 9) |

## 4. Последствия и триггеры пересмотра

- **Положительные:** согласованность свойств между BRAIM, IDS, адаптерами и внешними системами; меньше собственной словарной работы; готовность к экосистеме buildingSMART.
- **Цена/риски:** внешний сервис bSDD — только справочно (DICT-04 снимает runtime-зависимость); русского контента в bSDD сейчас мало — проектные таблицы пилота будут локальными (DICT-02); лицензии контента словарей проверять при подключении каждой таблицы (AQ-17).
- **Триггеры пересмотра:** появление русского/КСИ-контента в bSDD; стабильный v3 API; решение экспортировать пилотные таблицы как custom dictionary.
