# BAIM Roadmap

## Статус документа

- Версия: `0.1.0`
- Статус: Draft / рабочая дорожная карта
- Дата: 2026-09-25
- Проект: BAIM

## 1. Назначение

Эта дорожная карта фиксирует основные вехи проекта BAIM: от формализации требований и архитектуры до генерации BIM-модели, выпуска документации, строительства и эксплуатации.

Вехи не являются жёстким календарным планом. Каждая следующая веха начинается после проверки результатов предыдущей.

## 2. Общая модель BAIM

```text
Заказчик / архитектор
        ↓
Веб-форма и диалог
        ↓
AI Core
        ↓
Требования и аналитическая модель
        ↓
Варианты планировки и предварительные расчёты
        ↓
Web preview / визуализация
        ↓
Согласование
        ↓
Archicad Add-On / Connector
        ↓
Нативная BIM-модель Archicad
        ↓
Ручная архитектурная доработка
        ↓
Расчёты / проверки / смета
        ↓
Документация и строительство
        ↓
As-built / эксплуатационная модель
```

## 3. Статусы вех

- `PLANNED` — запланирована;
- `IN_PROGRESS` — выполняется;
- `BLOCKED` — заблокирована зависимостью или нерешённым вопросом;
- `VALIDATION` — находится на проверке;
- `DONE` — завершена и подтверждена;
- `DEFERRED` — отложена.

## 5. Детализация вех

### M0 — Vision & scope

**Цель:** определить, что именно строит BAIM и какие задачи не входят в первую версию.

**Результаты:**

- концепция AI-assisted BIM-проектирования;
- разделение ответственности AI Core и Archicad;
- жизненный цикл от идеи до эксплуатации;
- первичное понимание целевой аудитории;
- границы MVP.

**Критерий завершения:** цель проекта сформулирована, а ключевые компоненты согласованы.

### M1 — BAIM system architecture

**Цель:** описать техническую архитектуру.

**Результаты:**

- AI Core;
- web interface;
- analytical model;
- Archicad Add-On/Connector;
- IFC/IDS layer;
- calculation services;
- cost and construction layer;
- storage and versioning.

**Критерий завершения:** существует схема компонентов и потоков данных.

### M2 — EIM Maturity Profile

**Цель:** формализовать зрелость информационной модели.

**Результаты:**

- `G-I-C-A`;
- `GM`, `TOL`, `REL`;
- правила `min()`;
- required/actual profiles;
- статусы проверки;
- версия `0.1.0`.

**Критерий завершения:** спецификация может быть применена к тестовым элементам.

### M3 — Requirements model

**Цель:** превращать диалог с заказчиком в формализованные требования.

**Результаты:**

- профиль проекта;
- функциональная программа;
- ограничения участка;
- бюджет и сроки;
- предпочтения заказчика;
- неизвестные значения и допущения;
- подтверждённое ТЗ.

**Критерий завершения:** система может определить, каких данных не хватает для генерации варианта.

### M4 — Analytical building model

**Цель:** создать независимое представление здания до Archicad.

**Результаты:**

- помещения;
- площади;
- связи помещений;
- этажи;
- функциональные зоны;
- габариты;
- ориентация;
- строительные системы;
- требования и допущения;
- идентификаторы элементов.

**Критерий завершения:** модель может быть проверена без запуска Archicad.

### M5 — Variant generator

**Цель:** генерировать и сравнивать варианты.

**Результаты:**

- несколько планировочных вариантов;
- показатели площади;
- предварительная стоимость;
- ограничения и нарушения;
- преимущества и недостатки;
- история итераций;
- объяснение выбора.

**Критерий завершения:** система создаёт минимум три сравнимых варианта по одному ТЗ.

### M6 — Web preview

**Цель:** дать заказчику удалённый доступ к вариантам.

**Результаты:**

- 2D-план;
- простая 3D-визуализация;
- сравнение вариантов;
- карточка показателей;
- комментарии и выбор;
- фиксация решения заказчика.

**Критерий завершения:** заказчик может выбрать вариант без открытия Archicad.

### M7 — Archicad connector

**Цель:** создавать из аналитической модели нативные элементы Archicad.

**Результаты:**

- стены;
- перекрытия;
- крыши;
- окна и двери;
- помещения;
- уровни;
- свойства и классификации;
- стабильные идентификаторы;
- повторяемая генерация.

**Критерий завершения:** выбранный вариант создаётся в Archicad с контролируемым результатом.

### M8 — Architect editing workflow

**Цель:** сделать Archicad рабочим инструментом профессиональной доработки.

**Результаты:**

- ручные изменения архитектора;
- регистрация источника изменения;
- сравнение до/после;
- сохранение авторства;
- защита ручных решений;
- синхронизация с аналитической моделью.

**Критерий завершения:** ручная правка не уничтожается при следующей синхронизации.

### M9 — Validation and recalculation

**Цель:** определять последствия изменений.

**Результаты:**

- change detection;
- граф зависимостей;
- запуск необходимых расчётов;
- проверка EIM-профиля;
- IFC/IDS-проверки;
- список устаревших результатов;
- отчёт об ошибках.

**Критерий завершения:** система показывает, какие результаты необходимо пересчитать после изменения элемента.

### M10 — Documentation automation

**Цель:** автоматизировать выпуск проектного альбома.

**Результаты:**

- планы;
- фасады;
- разрезы;
- схемы;
- ведомости;
- спецификации;
- листы;
- оформление;
- экспорт PDF/IFC.

**Критерий завершения:** из проверенной модели выпускается воспроизводимый комплект документации.

### M11 — Cost and construction planning

**Цель:** связать модель с объёмами, стоимостью и строительством.

**Результаты:**

- объёмы работ;
- ведомость материалов;
- смета;
- календарный план;
- 4D-связи;
- 5D-связи;
- тендерный пакет.

**Критерий завершения:** изменения модели отражаются в связанных объёмах и стоимости.

### M12 — As-built and operation

**Цель:** продолжить использование модели после строительства.

**Результаты:**

- исполнительная модель;
- фактические параметры;
- оборудование;
- паспорта и документы;
- регламент обслуживания;
- история ремонтов;
- реконструкция;
- подготовка к сносу.

**Критерий завершения:** модель пригодна как информационная основа эксплуатации.

## 6. Рекомендуемый порядок реализации MVP

В первую очередь не нужно строить весь жизненный цикл. Для MVP достаточно:

```text
M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8
```

Практическое ядро MVP:

```text
анкета
→ ТЗ
→ аналитическая модель
→ три варианта
→ web preview
→ выбор
→ Archicad-модель
→ ручная доработка
```

После подтверждения этого цикла добавляются:

```text
M9 → M10 → M11 → M12
```

## 7. Контрольные демонстрации

### Demo 1 — ТЗ

Пользователь заполняет форму, система задаёт уточняющие вопросы и формирует подтверждённый профиль дома.

### Demo 2 — Варианты

AI Core генерирует три варианта планировки с площадями, ограничениями и предварительной стоимостью.

### Demo 3 — Согласование

Заказчик смотрит варианты в браузере, оставляет комментарии и выбирает один из них.

### Demo 4 — Archicad

Выбранный вариант автоматически создаётся как нативная Archicad-модель.

### Demo 5 — Ручная доработка

Архитектор меняет модель в Archicad, а система фиксирует изменения и не перезаписывает их.

### Demo 6 — Проверка

Система определяет устаревшие расчёты и показывает, какие проверки нужно повторить.
