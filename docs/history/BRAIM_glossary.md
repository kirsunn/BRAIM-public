## 3. Три «общих» модели — не путать

В стандарте они когда-то слиплись в одну строку «Общая (объединенная/федеративная) ИМ». Это три разные вещи.

| Термин | Что это | Вердикт |
|---|---|---|
| **Объединённая (merged)** | Всё в одном файле, один массив, авторство размыто | **Big Data — не наш путь** |
| **Федеративная** | Связка независимых моделей по ссылкам, авторство и ответственность сохранены | **наша** |
| **Сводная** | То же, что федеративная, в русской традиции | **наша** |
| **Опорная** | Итог стадии, публикуемая версия 00 | остаётся как есть |

Дословно из технологии: «Сводная ИМ — носит виртуальный характер, т.к. по сути не является единой моделью за пределами ПО (СОД), реализуемая на уровне ссылок».

То есть «мультивселенная» — это **федеративная = сводная**, а объединённая — явный антипример.

## 4. Шесть фасетов сущности

Фасет — грань, по которой **описываешь** объект. Их шесть, они ортогональны.

| Фасет | Вопрос |
|---|---|
| **Словарь** | как называется (СП-DD, bSDD, OmniClass) |
| **Классификация** | по каким граням делится (функция, форма, положение) |
| **Контейнер** | что внутри чего (здание → помещение → зона) |
| **Связь** | с чем соотнесена (граница, система, владелец) |
| **Набор** | что видно вместе (группировка, выборка) |
| **Проекция** | как подробно видно (Сумрак, MVD) |

**«Ось» — вычеркнута.** Это слово было лишним и склеивало фасет с полем имени.
**«Фасет» больше не фасет фасетов.** Тот член списка переименован в **«Классификация»**.

## 5. Поля имени файла

Поле — сегмент, из которого **собрано имя**. Это другой этаж, не фасеты.

`Итерация` · `Фаза` · `Статус` · `Представление` — плюс хвост `Релиз.Версия`.

Пример полного имени:
`ТЕХ-0747.16-0-П-П-ИОС-1.03.01-(ПЗ)-S3-RV-01.02.ifc`

## 6. Механизмы

| Механизм | Что делает | Владеем? |
|---|---|---|
| **Транзакция** | коммуникационное событие между двумя ролями: кто, что, когда, откуда, куда, почему | ссылаемся (ГОСТ Р 10.0.03-2019) |
| **Checkpoint** | снимок состояния BRAIM; фиксирует, чем мозг стал | да |
| **lifecycle_fork** | транзакция, порождающая новую итерацию; не переписывает прошлое, а добавляет ветвь (журнал — DAG) | да |
| **Quality Gate** | контрольная точка: Go / No-Go / Hold / Recycle | ссылаемся (ГОСТ Р 56862-2016) |
| **IDM** | карта процесса, взаимодействия и транзакций | ссылаемся |

**Две петли, не одна:**
- **Быстрая:** BRAIM → нулевая шина → ядро → назад. Это транзакции, «дыхание». Здесь версия и релиз.
- **Медленная:** BRAIM → BRAIM′. Это итерация, «взросление». Здесь checkpoint. Шина её не переносит: шина stateless, а итерация — память о том, кем мозг был.

## 7. Чем владеем / чем ссылаемся

**Владеем (наше):** итерация, схема нумерации релиз.версия, журнал транзакций, происхождение вариантов, нулевая шина, модель представлений.

**Ссылаемся (чужое):** состояния CDE (В работе / Общий доступ / Опубликовано / Архив), статус-коды, MVD, уровни проработки, качественные вехи.

**Отвергаем:** объединённая модель как единый массив (Big Data).

## 8. Прототип-ориентир: BuildBus

Интеграционная шина (ООО «Универо»). Совпадает с нашей нулевой шиной по функциям: транзакции, реестр стандартов, валидация при передаче, регистрация систем и ролей, история взаимодействия.

**Но два отличия:**
1. Уровень **документов**, а не элементов модели. Он не оперирует стеной, зоной, помещением. Наш этаж — элементы.
2. Контракт **закрытый** — риск зависимости (lock-in).

**Вывод:** берём функции, не берём уровень и не берём закрытость. Контракт нашей шины должен быть открытым.

## 10. Три фразы, которыми говорить

1. «BRAIM работает с **федеративной** моделью — совокупностью частных представлений, а не с объединённым массивом».
2. «**Сумрак** — это представление модели; федеративная модель — источник, сумраки — её проекции».
3. «Процесс не выпускает контейнер, пока **Quality Gate** не даст Go; при вечном цикле — Hold или No-Go».
