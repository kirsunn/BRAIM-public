## 1. Назначение

BAIM-LIMS — стандарт описания **состояния готовности информации** об объекте строительства. Он отвечает на вопрос «насколько элемент проработан, достоверен и готов к операции», а не «что это за элемент» и не «что требуется на этой стадии».

Стандарт задуман как **измерительный слой поверх** существующих систем классификации и нормирования (CoClass, CCS, КСИ, СП 333, ISO 19650, ISO/IEC 81346).

## 2. Область применения

Стандарт применим к цифровым информационным моделям (ЦИМ) объектов капитального строительства на всех стадиях жизненного цикла, включая параллельное сосуществование разных состояний внутри одного объекта.

---

## 3. Термины и определения

| Термин | Определение |
|---|---|
| **Профиль** | Запись, описывающая состояние готовности элемента по шести ортогональным осям |
| **Регистр** | Ось профиля (GE, IN, CO, MA, TO, RE) |
| **Namespace** | Верхнеуровневый трёхбуквенный код контейнера (PIM, AIM, BAIM) |
| **Итерация** | Внешний виток жизненного цикла объекта; реконструкция запускает новую итерацию |
| **Фаза** | Внутренний этап текущей итерации (C, P, S, U, D) |
| **Вселенная** | Проект или модель в целом |
| **Галактика** | Изолированная зона изменяемости, единица изоляции вариантности |
| **Пена** | Эфемерная среда генерации вариантов; пузырьки не имеют идентичности |
| **Вариант** | Выживший кандидат, получивший идентификатор (GUID) |
| **Дирижёр ядер** | Компонент, управляющий операциями над элементами и блокирующий недопустимые сочетания |

## 4. Базовые принципы

### 4.1 Ортогональность измерений

Измерения состояния независимы и **не взаимозаменяемы**:

1. Жизненный цикл (фаза и итерация) — *где во времени*
2. Состояние СОД — *можно ли использовать*
3. Зрелость (профиль) — *насколько готово*
4. Операция — *что разрешено*
5. Вариантность — *какая из альтернатив*

### 4.2 Внутри — своё, снаружи — перевод

Ядро говорит на собственном языке и не знает о национальных нормах. Соответствие внешним системам обеспечивается **слоем маппинга (anti-corruption layer)**, а не правкой ядра.

### 4.3 Один уровень вложенности — один тип токена

| Уровень | Тип токена | Пример |
|---|---|---|
| Namespace / контейнер | 3 заглавные буквы | `PIM`, `AIM`, `BAIM` |
| Регистр | 2 заглавные буквы | `GE`, `IN`, `CO` |
| Значение регистра | цифры | `2`, `111`, `4444` |
| Внутренняя позиция | цифра внутри значения | `4` в `MA4444` |

Буквы — навигация. Цифры — значение. Не смешивать.

### 4.4 Неизменяемость GUID

Идентификатор объекта инвариантен относительно его состояний. Он переживает смену итераций и схлопывание вариантов.

## 5. Профиль зрелости

### 5.1 Регистры

| Токен | Расшифровка | Смысл | Шкала |
|---|---|---|---|
| `GE` | GEometry | Геометрическая проработанность | 0, 2, 4, 6, 8, 10 |
| `IN` | INformation | Полнота атрибутивной информации | 0, 2, 4, 6, 8, 10 |
| `CO` | COnformance | Соответствие (проекту / факту) | 0, 1, 2 (триада) |
| `MA` | MAturity | Зрелость представления R-F-L-O | 4 позиции по 0–10 |
| `TO` | TOlerance | Точность | 0, 2, 4, 6, 8, 10 |
| `RE` | RErelationships | Полнота связей | 0, 2, 4, 6, 8, 10 |

**Зрелость MA — четыре внутренние позиции:**

| Позиция | Смысл |
|---|---|
| 1 | Размер (Size) |
| 2 | Форма (Form) |
| 3 | Местоположение (Location) |
| 4 | Ориентация (Orientation) |

Пример: `MA4444` — все четыре позиции на уровне 4.

> Примечание: буква `R` используется только как метка позиции в описании. В строке кода она не встречается — позиции кодируются цифрами. Коллизии нет.

### 5.2 Шкала CO (триада)

| Значение | Смысл |
|---|---|
| `000` | не задано |
| `100` | заявлено |
| `111` | соответствует проектной модели |
| `222` | подтверждено относительно факта |

### 5.3 Формат записи

```
{NAMESPACE}:GE{v}-IN{v}-CO{xyz}-MA{rfLo}-TO{v}-RE{v}
```

Пример:

```
PIM:GE2-IN2-CO111-MA4444-TO4-RE444
```

## 6. Пространство имён (namespace)

Верхний уровень — три заглавные буквы, по правилу «полное имя → трёхбуквенный код» (server → `SRV`).

| Namespace | Контейнер |
|---|---|
| `PIM` | Проектная информационная модель |
| `AIM` | Эксплуатационная информационная модель |
| `BAIM` | Единый namespace стандарта (при необходимости — поверх всего) |

## 7. Жизненный цикл

### 7.1 Фазы

| Фаза | Смысл |
|---|---|
| `C` | Концепция |
| `P` | Проектирование |
| `S` | Строительство |
| `U` | Эксплуатация |
| `D` | Демонтаж / утилизация |

Все коды ЖЦ — **только латиница**. Транслитерация кириллицы запрещена. Новые коды добавляются по английским сокращениям.

| Код | Смысл |
|---|---|
| `PIM-C-SUR` | Инженерные изыскания (surveys) |
| `PIM-C-FS` | Обоснование инвестиций (feasibility study) |
| `PIM-P-PR` | Проектная документация |
| `PIM-P-EX` | Рабочая документация |
| `PIM-S-CON` | Строительно-монтажные работы |
| `PIM-S-IE` | Исполнительная модель |
| `AIM-U-OPS` | Эксплуатация |
| `AIM-D-DEM` | Демонтаж |

### 7.2 Итерация

Жизненный цикл — не линейный. Реконструкция запускает **новую итерацию**, а не продолжает старую.

```
{ITER}:{PHASE}-{STAGE}
```

| Итерация | Что это | Фазы |
|---|---|---|
| 0 | исходный объект | C → P → S → U → D |
| 1 | реконструкция | C → P → S → U (от данных AIM) |
| n | следующая | … |

`PIM` / `AIM` — **производный** префикс: PIM = фазы C/P/S, AIM = фазы U/D. Контейнер вычисляется из пары (итерация + фаза).

### 7.3 Привязка к элементу

Жизненный цикл живёт **на уровне элемента**, а не модели. Это позволяет одному объекту честно содержать элементы в разных фазах и итерациях одновременно.

Пример (квартира):

| Помещение | Итерация | Фаза | Код |
|---|---|---|---|
| Комната 1 | 0 | строится | `0:S-CON` |
| Комната 2 | 1 | проектируется | `1:P-PR` |
| Комната 3 | 0 | демонтируется | `0:D-DEM` |
| Комната 4 | 0 | эксплуатируется | `0:U-OPS` |

## 10. Вариантность

### 10.1 Иерархия пространств

```
Universe (проект)
  └── Galaxy (зона изменяемости — единица изоляции)
        └── Foam (среда генерации — эфемерна, без идентичности)
              └── Variant (выживший кандидат — с GUID и профилем)
                    └── Decision (слияние 2 → 1)
```

**Правила:**

1. Граница галактики определяется **зоной изменяемости** (например, комната, узел, система).
2. Пена кипит внутри одной галактики и не покидает её.
3. Варианты из разных галактик не смешиваются.
4. GUID рождается только при выходе кандидата из пены.

### 10.2 Правило 2+1

- **2** — варианта на согласование (вход слияния).
- **+1** — результирующий вариант, который **добивают** до требуемой зрелости.

Третий вариант — не «победитель из двух», а **синтез**. Операция слияния определена для пары; для трёх и более — применяется попарное слияние (дерево).

> «Размножай сколько хочешь, но сливай по два.»

### 10.3 Статусы варианта

| Статус | Смысл |
|---|---|
| `proposed` | Предложен, участвует в сравнении |
| `active` | Проходит проверку |
| `result` | Результат слияния, добивается |
| `rejected` | Отклонён |
| `archived` | Сохранён как история |

### 10.4 Пример

```json
{
  "galaxy_id": "room_01",
  "foam": { "rules": "...", "filters": "..." },
  "variants": [
    { "id": "V0", "status": "proposed", "profile": "GE2-IN2-CO111-MA4444-TO4-RE444" },
    { "id": "V1", "status": "proposed", "profile": "GE4-IN4-CO111-MA6666-TO6-RE666" }
  ],
  "result": { "id": "V2", "status": "result", "profile": "GE4-IN4-CO222-MA8888-TO8-RE888" }
}
```

## 11. Дирижёр ядер

- Управляет операциями над элементами через **ворота**: операция разрешена только при достижении требуемого профиля (Required Profile).
- **Блокирует смешивание данных из разных вариантов** одного объекта: если геометрия помечена `V0`, а данные — `V1`, операция отклоняется.
- Для сравнения вариантов требует **Required-профиль сравнения** — все варианты должны его достичь.
- Разрешает **параллельные состояния** элементов (разные фазы и итерации в одной модели).

## 12. Классификация и маппинг

Классификация ортогональна профилю: она отвечает на «что это», профиль — на «насколько готово». Внутри кода профиля классификация не хранится.

| Ось | Вопрос | Чем описывается |
|---|---|---|
| Классификация | что это? | CoClass / CCS / КСИ |
| Жизненный цикл | где во времени? | фаза + итерация |
| Зрелость | насколько готово? | профиль |

### 12.1 CoClass / CCS

Обе системы построены на ISO 12006-2 и ISO/IEC 81346. CoClass — три категории: OBJECTS / PROPERTIES / ACTIVITIES, что совпадает с осями типов элементов, пула данных и ЖЦ.

### 12.2 КСИ (Россия)

Обязательный классификатор по ст. 57.6 ГрК РФ. Редакция 2025 — четыре категории: ресурсы, результаты, процессы, характеристики.

| Категория КСИ | Где в BAIM-LIMS |
|---|---|
| Ресурс | материалы слоёв, пул данных |
| Результат | типы элементов модели |
| Процесс | классификатор ЖЦ |
| Характеристика | регистр IN |

### 12.3 СП 333.1325800.2020

Уровни проработки ЦИМ: `A`, `B`, `C1`, `C2`, `D`, `G` (буквы `E` и `F` пропущены).

Уровень СП 333 — это **связка «стадия + полный набор требований»**, то есть соответствует **Required Profile целиком**, а не отдельному регистру.

| СП 333 | Этап ЖЦ | Код ЖЦ | Required-профиль (пример) |
|---|---|---|---|
| `A` | Изыскания | `PIM-C-SUR` | `MA4-IN0-CO100-...-RE444` |
| `B` | Проектирование | `PIM-P-PR` | `GE4-IN2-CO111-MA4444-TO6-RE666` |
| `C1` | Строительство (по проекту) | `PIM-S-CON` | `GE6-IN4-CO111-...` |
| `C2` | Строительство (исполнительная) | `PIM-S-IE` | `GE8-IN8-CO222-...` |
| `D` | Эксплуатация | `AIM-U-OPS` | `GE10-IN10-CO222-...` |
| `G` | Снос | `AIM-D-DEM` | `GE6-IN4-CO111-...` |

> **Разведение коллизий.** Фаза `C` в BAIM-LIMS (концепция) и уровень `C1/C2` в СП 333 (строительство) — разные вещи. Уровни СП 333 записываются с префиксом (`SP333-C1`), фазы BAIM-LIMS — без.

## 13. Версионирование

Стандарт использует семантическое версионирование:

- **MAJOR** — несовместимое изменение структуры профиля или смысла регистров.
- **MINOR** — добавление функциональности без ломающих изменений.
- **PATCH** — уточнения формулировок.

В ветке `0.x` (Draft) ломающие изменения допускаются в MINOR.

## 14. Открытые вопросы (для v1.1+)

1. **Связь фазы C и регистра CO** — возможно ли `CO000` при высокой зрелости.
2. **Граница галактики** — элемент, зона, система или объект; правила вложенности.
3. **Фильтр пены** — формальный критерий отбора кандидатов и роль человека.
4. **Мостик к нормативному ядру** — как классификация привязывает элемент к применимым расчётам.
5. **Судьба исходных вариантов** после слияния — архив или возможность возврата.
6. **GUID результата слияния** — тот же или новый (с родителями).
7. **Уровень привязки варианта** — элемент / система / объект.

## Приложение A. Сводный пример кода

```
PIM:0:C-PR|GE2-IN2-CO111-MA4444-TO4-RE444
```

Читается: проектная модель, нулевая итерация, фаза проектирования, профиль готовности — геометрия 2, информация 2, соответствие проектному, зрелость 4-4-4-4, точность 4, связи 4.
