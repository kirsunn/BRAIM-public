## 3. Три модели — разведены

| Термин | Что это | Вердикт |
|---|---|---|
| **Объединённая (merged)** | всё в одном файле, один массив | Big Data — НЕ наш путь |

## 4. Пять уровней версионирования

```
standard_version   — версия спецификации BRAIM (0.x → 1.0)  [метаданные]
iteration_snapshot — снимок проектной итерации (неизменяемый) [в имени: IT04]
release            — выпуск модели для обмена                  [в имени: R02]
revision           — внутренняя итерация работы над release    [в имени: .03]
cde_state          — состояние в СОД (WIP/SHR/PUB/ARC)         [метаданные CDE]
```

Имя файла: `IT04-R02.03`
- IT04 — четвёртый снапшот системы
- R02 — второй release (выпуск наружу)
- .03 — третья revision (рабочая версия внутри)

| Поле | В имени? | В снапшоте? | В метаданных CDE? |
|---|---|---|---|
| standard_version | нет | да | нет |
| iteration_id | да (IT04) | да | нет |
| release | да (R02) | да | нет |
| revision | да (.03) | да | нет |
| cde_state | нет | да | да |
| status (S0…A1) | нет | нет | да |
| MVD (представление) | нет | да | да |

### Структура снапшота

```
IterationSnapshot
├── iteration_id
├── project_id
├── baim_standard_version
├── description
├── created_at
├── scope
├── baseline_model_ref
├── affected_elements[]
├── affected_spaces[]
├── variants[]
├── decisions[]
├── cde_states[]
├── profiles[]
└── provenance[]
```

### Принципы снапшота

1. **Неизменяем** — после фиксации любое изменение = новая итерация
2. **Хранит контекст** — версию стандарта, правила, варианты, provenance, решения
3. **Основа сравнения** — дельта между IT0 и IT1, не «модель вообще»

### Поведение при событиях

| Событие | Снапшот | Release | Revision |
|---|---|---|---|
| Checkpoint (любой) | +1 | сброс R00 | .01 |
| Ревизия внутри release | та же | та же | +1 |
| Возврат из Hold | +1 (новый снимок) | сброс | .01 |
| Слияние веток (merge) | +1 (новый снимок) | сброс | .01 |

## 6. Механизмы

| Механизм | Что делает |
|---|---|
| **Транзакция** | коммуникационное событие между двумя ролями (ГОСТ Р 10.0.03-2019) |
| **Quality Gate** | контрольная точка: Go / No-Go / Hold / Recycle |
| **lifecycle_fork** | транзакция, создающая ветвь (DAG, не перезаписывает историю) |
| **Checkpoint** | фиксация состояния = снапшот |
| **Две петли** | быстрая (revision внутри release) и медленная (снапшот итерации) |

### lifecycle_fork — git для BIM

```
IT01 ─── IT02 ─── IT03 ─── IT05 (merge)
              └── IT04 ──┘
```

- Fork создаёт ветвь от снапшота
- Ветвь развивается независимо (свои release, revision)
- Merge создаёт новый снапшот (+1 к счётчику)
- История — DAG (направленный ациклический граф)
- Diff — графовый, по узлам и рёбрам, не по строкам

## 7. Класс vs свойство — три уровня

| Уровень | Что это | Кто решает | Можно менять? |
|---|---|---|---|
| **Класс (Entity)** | роль объекта: IfcWall, IfcDoor | схема IFC | нет |
| **Свойство (Pset)** | характеристики: FireRating, LoadBearing | проект | да |
| **Классификация** | внешний код: Uniclass, КСИ | внешняя система | да, метаданные |

### Правило

```
1. Меняются связи?           → КЛАСС
2. Меняется только значение? → СВОЙСТВО
3. Внешний код системы?      → КЛАССИФИКАЦИЯ (метаданные)
```

## 8. Граф vs таблицы

```
Граф — хранилище связей и состояний (источник истины)
Таблицы — проекция графа для агрегации и отчётов (производное)
```

| Задача | Граф | Таблицы |
|---|---|---|
| Связность, иерархия, пространственные отношения | да | — |
| Provenance, lifecycle_fork | да | — |
| Поиск пути, обход | да | — |
| Агрегация, ведомости, спецификации | — | да |
| Фильтрация по свойствам | — | да |
| Экспорт в Excel, отчёты | — | да |

## 9. Геометрический валидатор — три уровня

| Уровень | Что проверяет | Откуда данные |
|---|---|---|
| **Геометрический** | clash, расстояния, дубликаты, наличие | координаты из IFC |
| **Топологический** | замкнутость, ориентация граней, самопересечения, смежность | выводится из геометрии → граф |
| **Функциональный** | нормы: ширина коридора, пожарные отсеки, доступность | правила (IDS, bSDD) + геометрия + топология |

```
BRAIM → шина → геометрический валидатор (ядро)
                      ├── геометрические проверки
                      ├── топологические проверки (граф)
                      └── функциональные проверки (правила)
                    ↓
              отчёт BCF → BRAIM → Quality Gate → provenance снапшота
```

## 11. Владение: чем владеем / чем ссылаемся

| Слой | Чем владеем | Чем ссылаемся |
|---|---|---|
| BRAIM | словарь, правила, снапшоты, provenance | на ядро через шину |

## 12. BuildBus — ориентир с оговорками

- Уровень **документов**, не сущностей — наш слой ниже
- **Закрытый** контракт — наш должен быть открытым
- Берём: термин «транзакция», реестр стандартов, валидацию при передаче, регистрацию систем
- Не берём: уровень документов, lock-in

## 14. Три фразы для разговора с BIM-специалистом

1. «BRAIM работает с федеративной моделью — совокупностью частных представлений, а не с объединённым массивом».
2. «Сумрак — это представление модели; федеративная модель — источник, сумраки — её проекции».
3. «Процесс не выпускает контейнер, пока Quality Gate не даст Go; при вечном цикле — Hold или No-Go».
