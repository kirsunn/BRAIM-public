# AGR GeoJSON-приложение — формат и включение в стек BRAIM

**Дата:** 2026-10-15 · **Версия:** 0.1 · **Статус:** draft — нормативный акт подлежит подтверждению (см. §2)

---

## 1. Что это

**GeoJSON-приложение** — обязательный структурированный файл, сопровождающий 3D-модель (FBX) и/или IFC-модель при подаче на утверждение АГР в Москве. Создаётся сервисом «JSON-генератор» портала СтроимПросто (`/lk/agr#/generating-a-JSON-file`); эталонная модель Мосгоргеотреста поставляется с ним в комплекте (референсная реализация).

Референсный файл (эталон, скачан 2026-10-15): `_library/agr-moscow/etalon/T_Onezhskaya_Vl_14_B/SM_Onezhskaya_Vl_14_B.geojson` (15 095 байт, UTF-8 **с BOM**, по образцу RFC 7946).

## 2. Статус как стандарта

| Аспект | Значение |
|---|---|
| Базовый формат | **RFC 7946 (GeoJSON)** — FeatureCollection |
| Городское расширение | тип feature `ObjectFeature` (не входит в RFC 7946); **локальная СК Москвы** в geometry (Point [X, Y] в МГГТ-координатах, не WGS84) — отступление от RFC 7946, обязательное для контура АГР |
| Де-факто источник | JSON-генератор портала + эталонная модель (обе — артефакты ДГП/МГГТ) |
| Нормативный акт | подлежит подтверждению: вероятный носитель — «Требования к 3D-моделям» (распоряжение ДИТ и ДГП от 18.08.2026, `AGR_180826.pdf`) — **скан без текстового слоя**, проверка OCR/вручную (открытый вопрос) |

> Формат включается в стек BRAIM как **профиль `agr-geojson`** BRAIM Composition Format (ADR-016): наш `manifest.json` пакета — надмножество; экспорт/импорт профиля — controlled export через Zero Bus.

## 4. Проверки профиля (семейство `AGR-GEOJSON.*`)

| Правило | Что проверяет |
|---|---|
| `FIELD_COMPLETENESS` | обязательные поля заполнены (act_AGR — кроме стадии до утверждения) |
| `HEIGHT_CONSISTENCY` | h_relief + h_otn = h_abs (допуск — методика ТЭП) |
| `AREA_CONSISTENCY` | согласование s_naz + s_podz vs s_obsh vs spp_gns — по методике определения ТЭП (матрица СПП в ГНС); в эталоне найдено расхождение 25 м² — уточнить правило |
| `FNO_CODE_VALID` | FNO_code существует в классификаторе ФНО (словарь — получить; связка с КСИ) |
| `CROSS_ARTIFACT` | name/address/площади/высоты согласованы между GeoJSON ↔ ТЭП-XML ↔ IFC (единая проверка cross-artifact) |
| `CRS_PRESENT` | СК точки — московская локальная (манифест пакета фиксирует CRS явно) |

## 5. Связи со стеком

- **Standards Register v0.1:** добавить строку «RFC 7946 GeoJSON + профиль АГР (ObjectFeature, локальная СК)» со статусом «де-факто портал; нормативный акт — уточняется».
- **TEP_ATTRIBUTES_v0_1:** ключи GeoJSON влиты в сводную таблицу соответствий (XML ↔ GeoJSON ↔ IFC).
- **Attribute Registry:** `tep.*` атрибуты получают источник «AGR-GeoJSON» и ТЭП-XML одновременно (поле-дубли — правило согласования, не дублирование истины: истина — policy pack).
- **BRAIM Composition Format:** профиль `agr-geojson` — импорт входного пакета как есть; наш манифест не требует конвертации.

## 6. Открытые вопросы

1. Нормативный акт, определяющий формат (OCR скана распоряжения 18.08.2026 или визуальная проверка).
2. Правило AREA_CONSISTENCY: почему s_obsh ≠ s_naz + s_podz в эталоне (25 м²) — методика определения ТЭП (сервис «Матрица определения параметров в ЦИМ»).
3. Классификатор ФНО: получить полный словарь кодов (FNO_code), сопоставить с КСИ `FnS`.
4. Полный список полей для вкладки «Благоустройство» генератора (второй профиль формы).
