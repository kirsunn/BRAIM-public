## 4. Информационные конструкции (вывески)

- `signage_count` — количество вывесок; `signage_params` — подсветка, стелы, указатели (структура — уточнить по XML).

## 5. Связи с механизмами BRAIM

1. **Checks:** это готовый пул проверок класса Quantity/TEP (validation stack, §10 промпта): консистентность разбиений (наземная+подземная=общая; жилая+нежилая), заполненность обязательных, сравнение значений в IFC vs XML-ведомость (cross-artifact consistency!).
2. **JSON-приложение:** поля пересекаются (address, name, FNO_code, h_*, s_*) — сводная таблица соответствия — после получения обоих файлов.
3. **IdentityLink:** УИН, ГПЗУ/ППТ/ГЗК/КРТ/ППМ — внешние идентичности проекта; состав и версия — provenance.
4. **Attribute Registry:** каждый атрибут → `tep.*` id, тип, единица, владелец (сервис ТЭП), `bsdd_property_ref` — при наличии словарного определения.
