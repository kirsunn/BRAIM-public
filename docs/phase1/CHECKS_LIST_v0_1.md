# Phase 1 — Кандидаты проверок вертикального среза (draft v0.1)

**Дата:** 2026-10-15 · **Статус:** на утверждение автора (блокер №4 брифинга)
**Подход (решение автора):** гибрид — **IDS как механизм критериев** + собственные проверки, усиливающие критерии (ширина прохода, высота проёма, ФЗ-123, МГН). Нормативные значения — только с подтверждённым первоисточником (R-05, `no_ai_as_norm`): без редакции/пункта проверка не включается в policy pack, а помечается `needs_source`.
**Пилотный объект:** собственная АГР-модель (AD-03/AQ-11). На стадии АГР часть проверок может быть `NOT_APPLICABLE` — применимость фиксируется явно, не молча.

## 2. Сводка

- **Готовы к запуску сразу (1–6):** механизм есть (`braim.py` + Tapir-правило) — этого достаточно для первого демо «IFC → отчёт → Gate → snapshot».
- **Требуют первоисточников (7–10):** нужны редакции/пункты (СП 1.13130, СП 59.13330, ФЗ-123, СП 54/55) — работа domain-эксперта + подтверждение (P0-05 Standards Register).
- **Механизм для 7–10 — IDS:** свойства и геометрические пороги оформляются как IDS-политики; собственные проверки (ширина/высота) — IDS-совместимые правила в policy pack (гибридная модель правил, Layer Model §3).

## 3. Замечания

1. **СП 59.13330 (МГН) отсутствует в нашем реестре стандартов** — добавить в Standards Register v0.1 (P0-05) с проверкой актуальной редакции.
2. На стадии АГР проверки 7–10 частично неприменимы (нет финальной геометрии) — корректный результат `NOT_APPLICABLE` с обоснованием — это тоже демонстрация нашей модели статусов (Lifecycle §5).
3. Пороговые значения (0.9 м ширина МГН, REI-пределы и т.п.) в этот документ **не включены** сознательно — до подтверждения первоисточников.

## 4. Что нужно от автора

1. Утвердить состав 1–10 (или скорректировать).
2. Определить источник корпусных моделей: экспорты вашей АГР-модели из Archicad (сколько вариантов/итераций?).
3. Назначить время на подтверждение первоисточников 7–10 (или делегировать domain-эксперту позже).
