# BRAIM-LIMS v0.1

**BRAIM Layered Information Model Standard** — стандарт именования, версионирования и управления состоянием информационных контейнеров.

**Статус:** Draft v0.1  
**Дата:** 2026-10-04  
**Дедлайн Phase 0:** 2026-10-18

---

## 1. Область применения

BRAIM-LIMS применяется к:

- информационным контейнерам CDE (IFC/IDS/BCF/report);
- снапшотам итераций BRAIM;
- policy packs и mapping profiles;
- артефактам Golden Corpus.

Стандарт не заменяет EIR/BEP/контрактные naming convention заказчика. При конфликте приоритет у контрактных требований.

---

## 2. Пять уровней версионирования

Иерархия (сверху вниз):

```
standard_version   — версия спецификации BRAIM (0.x → 1.0)
  └── iteration_snapshot — снимок проектной итерации (неизменяемый)
        └── release — выпуск модели для обмена (несколько на снапшот)
              └── revision — внутренняя итерация работы над release
                    └── cde_state — состояние в СОД (WIP/SHR/PUB/ARC)
```

| Уровень | В имени файла? | В снапшоте? | В метаданных CDE? | Когда меняется |
|---|---|---|---|---|
| standard_version | нет | да | нет | редко, при несовместимых изменениях |
| iteration_id | да (`IT04`) | да | нет | каждый checkpoint |
| release | да (`R02`) | да | нет | каждый выпуск наружу |
| revision | да (`.03`) | да | нет | каждая рабочая версия внутри команды |
| cde_state | **нет** | да | **да** | при переходе между состояниями CDE |

## 3. Семантическое версионирование стандарта

```
MAJOR.MINOR.PATCH
```

| Поле | Когда меняется |
|---|---|
| `MAJOR` (0→1) | несовместимое изменение структуры/смысла |
| `MINOR` (0.1→0.2) | обратно совместимое добавление |
| `PATCH` (0.1.0→0.1.1) | исправление ошибок, правки формулировок |

Ветка `0.x` допускает breaking changes. Переход на `1.0.0` фиксирует стабильный API.

## 4. Именование файлов

### 4.1. Формат

```
{project_id}-{iteration_id}-{release_id}.{revision}.{extension}

Пример:
KZN-OIL-IT004-R01.03.ifc
```

| Компонент | Формат | Пример |
|---|---|---|
| `project_id` | `[A-Z0-9-]+` | `KZN-OIL-PUMP-STATION-2027` |
| `iteration_id` | `IT\d{3}` | `IT004` |
| `release_id` | `R\d{2}` | `R01` |
| `revision` | `\d{2}` | `03` |
| `extension` | `.ifc`, `.ids`, `.bcf`, `.zip` | `.ifc` |

### 4.2. Статус CDE — только в метаданных

| Поле | Куда | Почему |
|---|---|---|
| **Статус** (S0–A1, WIP/SHR/PUB/ARC) | **метаданные CDE** | меняется часто, по ISO 19650 — это метаданные |
| **Ревизия** (`P01.02`) | **имя файла** | выпуск, его видно глазами |
| **Представление** (MVD) | **метаданные** | стабильно, свойство контейнера |

**Ключевое правило:** смена статуса — **транзакция в CDE**, а не переименование файла.

## 5. Снапшот итерации

### 5.1. Структура

```
IterationSnapshot
├── iteration_id          — IT004
├── project_id            — KZN-OIL-PUMP-STATION-2027
├── baim_standard_version — 0.1.3
├── description           — "Реконструкция 4 этажа: коридор, 2 варианта"
├── created_at            — 2027-03-15T14:30:00+03:00
├── scope
│   ├── affected_elements[] — GUID IFC-элементов
│   ├── affected_spaces[]   — GUID помещений
│   └── baseline_model_ref  — "IT003"
├── variants[]            — пена: V-A, V-B
├── decisions[]           — D-001: select V-A
├── releases[]            — R01.01 (SHR), R01.02 (PUB)
├── cde_states[]          — WIP → SHR → PUB
└── provenance
    ├── git_commit_hash
    ├── author
    ├── branch
    └── parent_snapshot
```

### 5.2. Три принципа

1. **Снапшот неизменяем** — после фиксации любое изменение = новая итерация.
2. **Снапшот хранит контекст** — версия стандарта, scope, variants, provenance.
3. **Снапшот — основа сравнения** — дельта между IT0 и IT1, а не «модель вообще».

## 6. Итерация = счётчик снимков

| Событие | Счётчик итераций | Release | Revision |
|---|---|---|---|
| Checkpoint (любой) | +1 | сброс в R00.01 | — |
| Ревизия внутри итерации | та же | +1 к release | +1 |
| Возврат из Hold | +1 (новый снимок) | сброс | сброс |
| Слияние веток | +1 (новый снимок) | сброс | сброс |

**Один механизм для всех случаев:** сделали снимок → счётчик +1, release сбросился.

---

## 7. Lifecycle Fork (ветвление)

```
IT01 ─── IT02 ─── IT03 ─── IT05 (merge)
              └── IT04 ──┘
```

- Ветвь создаётся от снапшота — не перезаписывает историю.
- Развивается независимо — свои release, revision.
- Сливается обратно — создаёт **новый снапшот** (+1 к счётчику).
- История — DAG (направленный ациклический граф), не цепочка.

## 8. CDE State Machine

```
WIP (Work In Progress)
  ↓
SHR (Shared)
  ↓
PUB (Published)
  ↓
ARC (Archived)
```

Переходы:

- `WIP → SHR`: готово для координации
- `SHR → PUB`: утверждено для выпуска
- `PUB → ARC`: заменено новой версией
- `SHR → WIP`: возврат на доработку (Hold)

Состояние хранится **только в метаданных CDE**, не в имени файла.
